Cognito Authentication & Profile Sync

In this module you configure Amazon Cognito (reloop2-user-pool), define RBAC user groups (Admins, FinanceAdmins, Partners, Owners), enable Managed Login v2 on domain reloop2-auth, and create the Python 3.12 Post-Confirmation Lambda (reloop2-post-confirmation) that writes every newly verified user straight into reloop2-core-table.

Part A — Create User Pool & Configure Authentication

  1. Open Amazon Cognito -> User pools in ap-southeast-1 and click Create user pool.

  1. In the Set up your application wizard:
    • Choose Single-page application (SPA)
    • Name your application client reloop2-web-client
    • Select Email as the sign-in identifier and email, name as required sign-up attributes, then click Create user directory.

  1. Once Cognito creates the pool, review the generated User Pool ID and click Go to overview.

  1. On Overview, click Rename, enter reloop2-user-pool, and save.

  1. Under Authentication -> Authentication methods: verify Password (PASSWORD) is enabled and MFA is No MFA (Essentials tier default for smoother workshop onboarding; enable TOTP/SMS for production).

  1. Under Authentication -> Sign-in: confirm Email sign-in (alias_attributes = ["email"]) and case-insensitive usernames.

  1. Under Sign-up -> Attribute verification and user account confirmation: ensure self-service sign-up is on, email verification is active, and Account recovery uses Email only (verified_email, priority 1).

  1. Add workshop tags (Owner = team, Project = reloop2, Purpose = workshop) and confirm Deletion protection is Active (we will deactivate it explicitly in Module 5.13).

Part B — Create User Groups (RBAC)

  1. Go to User management -> Groups and create all 4 groups:
Group NamePrecedenceDescription
Admins1System operators and verifiers
FinanceAdmins1Finance reconcilers (bank / payout approvals)
Partners2Verified recycling and repair shops
Owners3Device sellers

Part C — Configure App Client (reloop2-web-client) & Managed Login Domain

  1. Open Applications -> App clients -> reloop2-web-client: check Authentication flows allow ALLOW_USER_SRP_AUTH and ALLOW_REFRESH_TOKEN_AUTH, access/ID token validity is 60 minutes, refresh token validity is 5 days, and Prevent user existence errors is enabled.

  1. Click the Login pages tab -> Edit Managed Login pages configuration:
    • Temporarily set Allowed callback URLs to http://localhost:5173/auth/callback
    • Temporarily set Allowed sign-out URLs to http://localhost:5173/ (we will append the CloudFront HTTPS URL in Module 5.8 once CloudFront is created!)
    • OAuth 2.0 grant types: Authorization code grant (code)
    • OpenID Connect scopes: openid, email, phone

  1. Go to Branding -> Domain. Cognito creates an auto-generated domain initially; create/replace with custom Cognito prefix reloop2-auth using Managed login version 2 (https://reloop2-auth.auth.ap-southeast-1.amazoncognito.com).

Part D — Create Post-Confirmation IAM Role & Python Lambda

When a user confirms their sign-up email code, Cognito synchronously calls reloop2-post-confirmation to insert their default Owner profile row into reloop2-core-table.

  1. Open IAM -> Roles -> Create role:
    • Trusted entity type: AWS service -> Lambda

  1. Attach AWS managed policy AWSLambdaBasicExecutionRole (if your lab account requires a Permissions Boundary policy such as TeamAppRoleBoundary, select it under Permissions boundary; personal accounts leave none).

  1. Set Role name: reloop2-post-confirmation-role, add tags, and click Create role.

  1. Open reloop2-post-confirmation-role -> Add permissions -> Create inline policy (JSON):

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PutUserProfile",
      "Effect": "Allow",
      "Action": "dynamodb:PutItem",
      "Resource": "arn:aws:dynamodb:ap-southeast-1:123456789012:table/reloop2-core-table"
    }
  ]
}

  1. Name the inline policy DynamoDBWriteAccess and save.

  1. Now open AWS Lambda -> Create function:
    • Author from scratch
    • Function name: reloop2-post-confirmation
    • Runtime: Python 3.12
    • Architecture: x86_64
    • Execution role: Use an existing role -> reloop2-post-confirmation-role

  1. Upload or deploy the Python handler lambda_function.py (reloop2-post-confirmation.zip), then click Save:
import datetime
import os
import boto3

dynamodb = boto3.client("dynamodb")
TABLE_NAME = os.environ["TABLE_NAME"]

def lambda_handler(event, context):
    if event.get("triggerSource") != "PostConfirmation_ConfirmSignUp":
        return event

    attrs = event["request"]["userAttributes"]
    user_id = attrs["sub"]
    email = attrs.get("email", "")
    name = attrs.get("name", "Unknown")
    role = "Owner"
    timestamp = datetime.datetime.utcnow().isoformat() + "Z"

    try:
        dynamodb.put_item(
            TableName=TABLE_NAME,
            Item={
                "PK": {"S": f"USER#{user_id}"},
                "SK": {"S": "PROFILE"},
                "GSI1PK": {"S": f"ROLE#{role}"},
                "GSI1SK": {"S": f"USER#{user_id}"},
                "email": {"S": email},
                "fullName": {"S": name},
                "role": {"S": role},
                "status": {"S": "ACTIVE"},
                "createdAt": {"S": timestamp},
            },
            ConditionExpression="attribute_not_exists(PK)",
        )
    except Exception as exc:
        print(f"Failed to write user to DynamoDB: {exc}")

    return event

  1. Verify Configuration -> General configuration (128 MB, 3 sec timeout) and add Environment variable:
    • Key: TABLE_NAME
    • Value: reloop2-core-table

Part E — Attach Post-Confirmation Trigger in Cognito

  1. Return to Cognito User Pool reloop2-user-pool -> Extensions -> Lambda triggers, and click Add Lambda trigger.

  1. Configure:
    • Trigger type: Sign-up
    • Sign-up trigger: Post confirmation trigger
    • Lambda function: reloop2-post-confirmation Then click Add Lambda trigger (Cognito automatically adds the Lambda resource-based invoke permission).
